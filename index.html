What is a UUID duplicate problem?

Source: IBM License Metric Tool 9.2.0 — VM Manager Statuses · VM Manager Tool

Each virtual machine must have a unique UUID or, in case of Hyper-V, a unique BIOSSerialNumber. When a UUID or BIOSSerialNumber identifies more than one VM, both VMs are discarded from the results. The problem occurs most frequently on VMware and is usually caused by virtual machines being deployed from catalog templates in vCloud Director (which assigns the same BIOS UUID by default) or by virtual machines being cloned without changing their UUIDs.

What is the VM Manager Tool?

Source: IBM License Metric Tool 9.2.0 — VM Manager Tool

The VM Manager Tool is a component of IBM License Metric Tool that collects capacity data from virtualization hosts. It connects to each configured hypervisor endpoint and retrieves the list of all virtual machines and their hardware attributes, including the UUID used by ILMT for VM identification.

Each hypervisor connection is defined in a vmmconf_*.properties file. The VM Manager Tool can be deployed in four modes: local (on the ILMT server), central (on the BigFix server), distributed (on a BigFix client), or disconnected. On Hyper-V, ILMT uses the BIOSSerialNumber field to uniquely identify each VM; on VMware it uses the BIOS UUID (BIOSUuid). When a UUID or BIOSSerialNumber identifies more than one VM, both VMs are discarded from the results.

🖥️

Hyper-V

Connects via WS-Management (WinRM) to the Hyper-V host. Retrieves BIOSSerialNumber from Msvm_VirtualSystemSettingData for each VM. Each VM must have a unique BIOSSerialNumber.

☁️

VMware vSphere / ESXi

Connects to vCenter or directly to ESXi. Retrieves the BIOS UUID (BIOSUuid) from each VM's config. The problem occurs most frequently on VMware — virtual machines deployed from catalog templates in vCloud Director are assigned the same BIOS UUID by default, or virtual machines are cloned without changing their UUIDs.

🗄️

Other supported types

Also supports KVM/libvirt, XenServer (Citrix Hypervisor), Oracle VM, Red Hat OpenShift, and public clouds. Each VM must have a unique UUID; on XenServer, XenTools must be installed on each guest for UUID retrieval.

🔍 What to Analyze for a Duplicate UUID

When a duplicate UUID is detected, the following points must be investigated to understand scope, root cause, and impact before remediation.

Check 1
🖥️ Which host carries the duplicate?
Identify the exact Hyper-V / ESXi / KVM host where 2 or more VMs share the same BIOSSerialNumber.
  • Cross-reference the REMOVING DUPLICATED GUEST trace log entry with the host WMI output
  • Note the host FQDN / IP — this is where the fix must be applied
  • If multiple hosts share the same UUID, each must be fixed independently
Check 2
📋 Which VMs share the UUID?
List every VM on that host whose BIOSSerialNumber matches the duplicate value.
  • One VM is typically the original; others are clones or templates deployed without UUID regeneration
  • Check VM creation dates and names to identify the clone chain
  • All but one VM must have their UUID replaced with a new unique value
Check 3
⚠️ How many ILMT VMs are silently dropped?
ILMT discards all but one VM per UUID — understand the license calculation impact.
  • Count the duplicate VMs: N − 1 VMs are invisible to ILMT license calculations
  • If those VMs run IBM software (e.g. Db2, WebSphere, MQ), your reported PVU/RVU count is understated
  • Check the ILMT Software Catalog report before and after the fix
Check 4
🔎 What is the root cause?
Determine why the duplicate UUID was created to prevent recurrence.
  • Cloning without UUID reset — VM cloned or exported/imported without regenerating BIOS UUID
  • Template deployment — VM template captured with a fixed UUID; all deployed VMs inherit it
  • P2V / V2V migration — physical-to-virtual or cross-hypervisor migration preserved the original UUID
  • Snapshot restore — restoring an older snapshot re-applied a UUID that a sibling VM already uses

# Find VM datastore path vim-cmd vmsvc/getallvms | grep "<VM_NAME>" # SSH to ESXi host, then: vi /vmfs/volumes/<datastore>/<VM_NAME>/<VM_NAME>.vmx # Find and change these lines (or remove them — VMware will auto-generate new ones on next power-on): # uuid.bios = "xx xx xx xx xx xx xx xx-xx xx xx xx xx xx xx xx" # uuid.location = "xx xx xx xx xx xx xx xx-xx xx xx xx xx xx xx xx" # Save file, then power on the VM # VMware will prompt: "I Moved It" or "I Copied It" — select "I Copied It" # This forces generation of a new UUID

Set new UUID via PowerCLI

Connect-VIServer -Server <vcenter_or_esxi> $vm = Get-VM -Name "<VM_NAME>" $spec = New-Object VMware.Vim.VirtualMachineConfigSpec $spec.uuid = [guid]::NewGuid().ToString() $vm.ExtensionData.ReconfigVM($spec) Write-Host "New UUID assigned: $($spec.uuid)"
4

Verify and rescan ILMT

Connect-VIServer -Server <vcenter_or_esxi> Get-VM -Name "<VM_NAME>" | Select-Object Name, @{N='BiosUUID';E={$_.ExtensionData.Config.BIOSUuid}}

Then in ILMT: go to Management → Data Import → Import Now to force an import, then check Management → VM Managers to confirm the status no longer shows "duplicated UUIDs discarded".
