What is a UUID duplicate problem?

IBM License Metric Tool (ILMT) identifies virtual machines by their BIOSSerialNumber (UUID). When two or more VMs share the same UUID — typically due to cloning, template deployment, or migration without UUID regeneration — ILMT treats them as a single machine. This silently discards VMs from license calculations, causing incorrect software license counts.

What is a VM Manager?

A VM Manager is a connection configured in ILMT that scans a hypervisor host or management server to discover all virtual machines and their hardware attributes. ILMT uses the BIOSSerialNumber attribute (also called ILMT UUID) from each VM to uniquely identify it in the license calculation engine.

VM Manager connections are stored as vmmconf_N.properties files on the ILMT server. Each connection targets one hypervisor endpoint.

🖥️

Hyper-V

Connects via WS-Management (WinRM) to enumerate Msvm_VirtualSystemSettingData and retrieve BIOSSerialNumber per VM.

☁️

VMware vSphere / ESXi

Connects via VMware vSphere API (SOAP/REST) to retrieve the BIOSUuid and InstanceUuid from VM config.

🗄️

Oracle VM / KVM

Connects via Oracle VM Manager REST API or libvirt to retrieve guest UUIDs assigned at VM creation time.

VM Manager Statuses

Source: IBM License Metric Tool 9.2 — VM Manager Statuses documentation

StatusSeverityDescription & What to Do
OK OK The VM Manager connection is working correctly. The last scan completed successfully and data was imported into ILMT without issues.
OK - duplicated UUIDs discarded WARNING The scan succeeded but ILMT detected virtual machines sharing identical BIOSSerialNumber (UUID) values. The duplicate entries were silently dropped from the import. This is the primary signal that duplicate UUIDs exist on this hypervisor host. Use the Uploader and Analyzer to identify which VMs are affected, then use the Fixer to resolve.
Error ERROR The VM Manager scan failed. ILMT could not connect to or authenticate with the hypervisor endpoint. Check network connectivity, credentials, and that the hypervisor management service is running. Review trace.log_vmmconf_N.log for details.
Connection failed ERROR ILMT could not establish a network connection to the VM Manager endpoint (wrong IP/hostname, firewall blocking port, or service down). Verify the URL in the VM Manager configuration and test connectivity with Test-NetConnection (PowerShell) or telnet.
Authentication failed ERROR ILMT connected to the endpoint but the credentials (username/password) were rejected. Update the VM Manager credentials in ILMT and ensure the account has sufficient permissions on the hypervisor.
Never scanned INFO The VM Manager connection has been configured but has not yet run a scan. Trigger a manual scan from Manage → VM Managers → Run Now or wait for the next scheduled scan cycle.
Pending INFO A scan has been queued or is currently in progress. Wait for the scan to complete before interpreting results.
Partial data collected WARNING The scan ran but could not retrieve full inventory — some hosts or VMs were unreachable. ILMT imported what it could. Check which hosts returned errors in the trace log and verify those hosts are accessible.
No VM Manager data WARNING A VM was discovered by ILMT (e.g. via agent) but no corresponding VM Manager scan data exists for it. The VM's physical host topology is unknown to ILMT. Configure a VM Manager for that hypervisor host.
Outdated data WARNING The last successful scan was too long ago (beyond the configured data freshness threshold). ILMT may use stale VM inventory. Investigate why recent scans are failing and resolve the underlying connection issue.
Key signal: If any VM Manager row shows OK - duplicated UUIDs discarded, go to the Commands tab, select your hypervisor type, run the provided query on the affected host, then upload the output to the Uploader for analysis.

Commands

Select your virtualization technology below. The tool generates the exact commands to run on your hypervisor host to list all VMs and their BIOSSerialNumbers (ILMT UUIDs). Save the output as a .txt file and upload it to the Uploader.

Run on the Hyper-V host: Open PowerShell as Administrator on the Hyper-V host (not inside a VM). Replace <computername> with the host's name or IP address.

Primary WMI query — retrieves ElementName (VM display name), VirtualSystemIdentifier, and BIOSSerialNumber (the ILMT UUID) for every VM on the host. Save output with Out-File and upload to Uploader.

get-wmiobject -Query "SELECT ElementName, VirtualSystemIdentifier, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" -namespace 'root/Virtualization/V2' -computername <computername>

Save to file:

get-wmiobject -Query "SELECT ElementName, VirtualSystemIdentifier, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" -namespace 'root/Virtualization/V2' -computername <computername> | Out-File "C:\Temp\<computername>-uuids.txt"
get-wmiobject -Query "SELECT ElementName, VirtualSystemIdentifier, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" ` -namespace 'root/Virtualization/V2' ` -computername <computername> | Select-Object ElementName, VirtualSystemIdentifier, BIOSSerialNumber | Export-Csv -Path "C:\Temp\<computername>-uuids.csv" -NoTypeInformation

Returns only BIOSSerialNumbers that appear on more than one VM on this host:

$vms = get-wmiobject -Query "SELECT ElementName, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" ` -namespace 'root/Virtualization/V2' ` -computername <computername> $vms | Group-Object BIOSSerialNumber | Where-Object { $_.Count -gt 1 } | Select-Object Name, Count, @{N='VMs';E={($_.Group.ElementName -join ', ')}} | Format-Table -AutoSize
$hosts = @("HOST01", "HOST02", "HOST03") # edit this list $results = foreach ($h in $hosts) { get-wmiobject ` -Query "SELECT ElementName, VirtualSystemIdentifier, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" ` -namespace 'root/Virtualization/V2' ` -computername $h | Select-Object @{N='Host';E={$h}}, ElementName, VirtualSystemIdentifier, BIOSSerialNumber } $results | Export-Csv -Path "C:\Temp\all-hosts-uuids.csv" -NoTypeInformation Write-Host "Saved to C:\Temp\all-hosts-uuids.csv"

Alternative using the Hyper-V module (Windows Server 2012 R2+):

Get-VM -ComputerName <computername> | ForEach-Object { $vm = $_ [PSCustomObject]@{ VMName = $vm.Name State = $vm.State BIOSSerialNumber = (Get-WmiObject -Namespace 'root/Virtualization/V2' ` -Class Msvm_VirtualSystemSettingData ` -Filter "ElementName='$($vm.Name)'" ` -ComputerName <computername>).BIOSSerialNumber } } | Format-Table -AutoSize
Requires VMware PowerCLI: Install with Install-Module VMware.PowerCLI -Scope CurrentUser. Connect to vCenter or directly to ESXi.
Connect-VIServer -Server <vcenter_or_esxi> Get-VM | Select-Object Name, @{N='BiosUUID';E={$_.ExtensionData.Config.BIOSUuid}}, @{N='InstanceUUID';E={$_.ExtensionData.Config.InstanceUuid}}, @{N='Host';E={$_.VMHost.Name}} | Export-Csv -Path "C:\Temp\vmware-uuids.csv" -NoTypeInformation Write-Host "Saved to C:\Temp\vmware-uuids.csv"
Connect-VIServer -Server <vcenter_or_esxi> Get-VM | Select-Object Name, @{N='BiosUUID';E={$_.ExtensionData.Config.BIOSUuid}}, @{N='Host';E={$_.VMHost.Name}} | Group-Object BiosUUID | Where-Object { $_.Count -gt 1 } | ForEach-Object { Write-Host "=== DUPLICATE UUID: $($_.Name) ===" -ForegroundColor Red $_.Group | Format-Table Name, Host -AutoSize }

Run directly on ESXi host via SSH:

# List all registered VMs vim-cmd vmsvc/getallvms # Get config of a specific VM (replace <vmid> with ID from above): vim-cmd vmsvc/get.config <vmid> | grep -i uuid # All VMs with their UUID in one command: for vmid in $(vim-cmd vmsvc/getallvms 2>/dev/null | tail -n +2 | awk '{print $1}'); do name=$(vim-cmd vmsvc/get.config $vmid 2>/dev/null | grep 'displayName' | awk -F'"' '{print $2}') uuid=$(vim-cmd vmsvc/get.config $vmid 2>/dev/null | grep 'uuid' | head -1 | awk -F'"' '{print $2}') echo "$uuid $name" done

VMware VMs have two UUIDs. ILMT uses the BIOS UUID (BIOSUuid). The Instance UUID is unique per vCenter inventory item and does not cause ILMT duplicates.

Connect-VIServer -Server <vcenter_or_esxi> Get-VM | ForEach-Object { [PSCustomObject]@{ Name = $_.Name BiosUUID = $_.ExtensionData.Config.BIOSUuid # ← ILMT uses this InstanceUUID = $_.ExtensionData.Config.InstanceUuid # ← unique, no ILMT issue Host = $_.VMHost.Name } } | Sort-Object BiosUUID | Format-Table -AutoSize
Run on the KVM host: Requires libvirt-client (virsh) installed. Run as root or with sudo.
# Local host virsh list --all --uuid # Remote host via SSH virsh -c qemu+ssh://root@<hostname>/system list --all --uuid # Save to file virsh list --all --uuid > /tmp/$(hostname)-uuids.txt
for vm in $(virsh list --all --name); do uuid=$(virsh domuuid "$vm" 2>/dev/null) echo "$uuid $vm" done | sort
for vm in $(virsh list --all --name); do uuid=$(virsh domuuid "$vm" 2>/dev/null) echo "$uuid $vm" done | sort | awk 'seen[$1]++ { print "DUPLICATE UUID:", $0 }'
virsh dumpxml <vmname> | grep -A2 -i uuid # Look for: # <uuid>xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx</uuid> # <entry name='manufacturer'>...</entry>
Oracle VM Manager REST API: Requires Oracle VM Manager credentials. Use the REST API or the OVM CLI tool.
# List all VMs (replace <ovm-host>, <user>, <password>) curl -s -u <user>:<password> \ "https://<ovm-host>:7002/ovm/core/wsapi/rest/Vm" \ -H "Accept: application/json" | python3 -m json.tool # Extract name and UUID fields: curl -s -u <user>:<password> \ "https://<ovm-host>:7002/ovm/core/wsapi/rest/Vm" \ -H "Accept: application/json" | \ python3 -c "import sys,json; vms=json.load(sys.stdin); [print(v.get('id',{}).get('value',''),v.get('name','')) for v in vms]"
# Connect to OVM Manager CLI ssh root@<ovm-host> # In OVM CLI: /u01/app/oracle/ovm-manager-3/ovm_tools/bin/ovm_admin.sh list Vm
Azure Stack HCI uses Hyper-V underneath: All standard Hyper-V PowerShell commands apply. Use the WMI query below on each cluster node.
get-wmiobject -Query "SELECT ElementName, VirtualSystemIdentifier, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" -namespace 'root/Virtualization/V2' -computername <hci-node-name>
# Get all cluster nodes automatically $nodes = (Get-ClusterNode -Cluster <cluster-name>).Name $results = foreach ($node in $nodes) { get-wmiobject ` -Query "SELECT ElementName, VirtualSystemIdentifier, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" ` -namespace 'root/Virtualization/V2' ` -computername $node | Select-Object @{N='Node';E={$node}}, ElementName, VirtualSystemIdentifier, BIOSSerialNumber } $results | Export-Csv -Path "C:\Temp\hci-all-nodes-uuids.csv" -NoTypeInformation

🔧Fixer

Generates the exact commands to fix duplicate UUIDs on your hypervisor. Run the Analyzer first to identify affected VMs, then select your hypervisor type below.

Run the Analyzer first: Upload files and run the Analyzer to populate duplicate findings before using the Fixer.
Before you begin: Always snapshot or backup the VM configuration before modifying UUID values. Power off the VM first.
1

Identify the affected VM and host from the Analyzer

Go to the Analyzer tab → expand the duplicate group → note the VM name and Hyper-V host FQDN.

2

Power off the affected VM

Stop-VM -Name "<VM_NAME>" -ComputerName <computername> -Force
3

Generate a new unique UUID

[guid]::NewGuid().ToString().ToUpper() # Example: A1B2C3D4-E5F6-7890-ABCD-EF1234567890
4a

Fix — Export and Re-import with new ID Recommended

Hyper-V automatically assigns a fresh unique UUID when re-importing with -GenerateNewId.

# Export VM Export-VM -Name "<VM_NAME>" -Path "C:\Temp\VMExport" -ComputerName <computername> # Import as new VM with fresh UUID Import-VM -Path "C:\Temp\VMExport\<VM_NAME>\Virtual Machines\<config>.vmcx" ` -GenerateNewId -ComputerName <computername>

After re-import: start the new VM, verify it works, then delete the original.

4b

Fix — Set new BIOSSerialNumber via WMI (advanced)

Directly modify the BIOSSerialNumber on the existing VM configuration. Use only if export/re-import is not feasible.

$vmName = "<VM_NAME>" $computer = "<computername>" $newUUID = "[guid]::NewGuid().ToString()" # run separately to get value # Get VM settings object $vmSettings = Get-WmiObject -Namespace 'root/Virtualization/V2' ` -Class Msvm_VirtualSystemSettingData ` -Filter "ElementName='$vmName'" ` -ComputerName $computer # Modify BIOSSerialNumber $vmSettings.BIOSSerialNumber = $newUUID # Apply via management service $mgmtSvc = Get-WmiObject -Namespace 'root/Virtualization/V2' ` -Class Msvm_VirtualSystemManagementService ` -ComputerName $computer $mgmtSvc.ModifySystemSettings($vmSettings.GetText(1))
5

Verify the fix

get-wmiobject -Query "SELECT ElementName, BIOSSerialNumber FROM Msvm_VirtualSystemSettingData" ` -namespace 'root/Virtualization/V2' ` -computername <computername> | Where-Object { $_.BIOSSerialNumber -ne "" } | Select-Object ElementName, BIOSSerialNumber | Sort-Object BIOSSerialNumber
6

Trigger data import in ILMT

In ILMT: go to Management → Data Import → Import Now to force an immediate data import cycle.

7

Verify VM Manager status

Go to Management → VM Managers and check the status of the Hyper-V connection. It should no longer show "OK - duplicated UUIDs discarded". If the status is OK, the duplicate UUID has been resolved.

Before you begin: Take a VM snapshot before modifying UUID values. Power off the VM first.
1

Power off the affected VM

Connect-VIServer -Server <vcenter_or_esxi> Stop-VM -VM "<VM_NAME>" -Confirm:$false
2

Edit the .vmx file to assign a new UUID Recommended

The BIOS UUID is stored in the .vmx file as uuid.bios. SSH to the ESXi host and edit:

# Find VM datastore path vim-cmd vmsvc/getallvms | grep "<VM_NAME>" # SSH to ESXi host, then: vi /vmfs/volumes/<datastore>/<VM_NAME>/<VM_NAME>.vmx # Find and change these lines (or remove them — VMware will auto-generate new ones on next power-on): # uuid.bios = "xx xx xx xx xx xx xx xx-xx xx xx xx xx xx xx xx" # uuid.location = "xx xx xx xx xx xx xx xx-xx xx xx xx xx xx xx xx" # Save file, then power on the VM # VMware will prompt: "I Moved It" or "I Copied It" — select "I Copied It" # This forces generation of a new UUID
3

Set new UUID via PowerCLI

Connect-VIServer -Server <vcenter_or_esxi> $vm = Get-VM -Name "<VM_NAME>" $spec = New-Object VMware.Vim.VirtualMachineConfigSpec $spec.uuid = [guid]::NewGuid().ToString() $vm.ExtensionData.ReconfigVM($spec) Write-Host "New UUID assigned: $($spec.uuid)"
4

Verify and rescan ILMT

Connect-VIServer -Server <vcenter_or_esxi> Get-VM -Name "<VM_NAME>" | Select-Object Name, @{N='BiosUUID';E={$_.ExtensionData.Config.BIOSUuid}}

Then in ILMT: go to Management → Data Import → Import Now to force an import, then check Management → VM Managers to confirm the status no longer shows "duplicated UUIDs discarded".

Before you begin: Back up the VM XML definition. Power off the VM before editing.
1

Power off the affected VM

virsh shutdown <vmname> # If it doesn't respond: virsh destroy <vmname>
2

Backup and edit the VM XML to assign a new UUID

# Backup current XML virsh dumpxml <vmname> > /tmp/<vmname>-backup.xml # Generate a new UUID NEW_UUID=$(uuidgen) echo "New UUID: $NEW_UUID" # Edit the XML (change the <uuid> element) virsh edit <vmname> # In the editor, find: <uuid>old-uuid-here</uuid> # Replace with: <uuid>$NEW_UUID</uuid> # Save and exit
3

Start the VM and verify

virsh start <vmname> virsh domuuid <vmname>
